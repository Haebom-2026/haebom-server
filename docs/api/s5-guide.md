# S5 API: 화면 안내 (#16 guide)

- 작성일: 2026-11-26
- 대상: 고령자 앱
- 상태: **dev 배포 완료** (PR Haebom-2026/haebom-server#7, 검토 반영 `guide@v2`)
- 기준: 지침서 3장·5.7, [서버 기획](../server-plan.md) 5.1·5.3, 고령자 앱 검토 답변 4.2 (노드 형식)

어르신이 말한 일과 지금 화면의 접근성 요소를 보내면, **다음에 할 행동 하나**를 돌려줍니다. 서버는 Claude Sonnet 5.5로 판단하고, 모델 출력을 지금 화면에 맞는지 다시 확인한 뒤 응답합니다.

공통 규칙(Base URL, 인증, 오류 형식)은 [S1 문서 1장](s1-users-links.md#1-공통)과 같습니다.

> **먼저 `POST /v1/users/me`로 `role: "elder"` 등록이 필요합니다.** 등록하지 않은 토큰이나 보호자 토큰으로 부르면 403입니다.

---

## 1. 언제 부르나

- **로컬 플래너가 처리하지 못하는 일**일 때만 부릅니다. 연락처 추가, 유튜브 검색, 정부24, 앱 열기처럼 앱이 아는 일은 앱이 직접 안내합니다.
- 명령 하나에 **여러 번** 부를 수 있습니다. 화면이 바뀌어 다음 단계를 정해야 할 때마다 부릅니다.
- **부르지 않는 경우**: 비밀번호·인증번호 입력 칸이 있는 화면. 서버도 한 번 더 거르지만(4장), 앱에서 먼저 보내지 않는 게 원칙입니다.
- **은행·금융 앱도 안내합니다.** 민감하다는 표시(L1 "보호자에게 알릴까요?" 팝업, L2 승인)는 지침서 4장대로 **명령 단계에서 앱이 먼저** 띄우고, 그다음 화면 안내에 guide를 씁니다. 송금 확정 버튼은 서버가 누르라고 하지 않고 본인이 확인하도록 안내합니다.
  - ⚠️ 고령자 앱은 지금 은행 패키지(`bank`·`kbstar`·`toss`·`shinhan`·`wooribank`) 화면을 보내지 않으니, 이 필터를 **guide 요청에서는 풀어야** 합니다. 디버그 뷰어 전송에서는 그대로 두는 걸 권합니다.

- **응답을 기다리지 않습니다.** 자막에 "잠깐만요, 살펴보고 있어요"만 띄우고 화면을 막지 않습니다 (지침서 3.4).

## 2. 요청

```
POST /v1/elder/guide
Authorization: Bearer <Firebase ID 토큰>
Content-Type: application/json; charset=utf-8
```

```json
{
  "requestId": 108,
  "goal": "OPEN_APP",
  "utterance": "카카오톡 열어 줘",
  "slots": { "app": "카카오톡" },
  "history": ["홈 화면으로 가세요."],
  "screen": {
    "pkg": "com.sec.android.app.launcher",
    "width": 1080,
    "height": 2640,
    "nodes": [
      {
        "i": 0,
        "t": "카카오톡",
        "c": "android.widget.TextView",
        "b": [60, 1500, 300, 1760],
        "clickable": true
      },
      {
        "i": 1,
        "d": "앱스",
        "c": "android.widget.ImageView",
        "b": [440, 2300, 640, 2500],
        "clickable": true
      }
    ]
  }
}
```

| 필드                            | 필수 | 규칙                                                                                                                                |
| ------------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `requestId`                     | ✅   | 0 이상 정수. 서버가 그대로 돌려줍니다 (늦은 응답 버리기용)                                                                          |
| `goal`                          | ✅   | 1~40자. 앱 IntentParser의 목표: `ADD_CONTACT`, `YOUTUBE`, `GOV24`, `BANK`, `OPEN_APP`, `UNKNOWN`                                    |
| `utterance`                     |      | 어르신이 한 말 (200자까지)                                                                                                          |
| `slots`                         |      | 말에서 뽑은 값. 키 40자, 값 100자까지 (예: `app`, `query`, `name`, `phone`)                                                         |
| `history`                       |      | 지금까지 안내한 문장, 오래된 것부터 최대 10개 (각 200자)                                                                            |
| `screen.pkg`                    | ✅   | 지금 화면의 앱 패키지                                                                                                               |
| `screen.width`, `screen.height` | ✅   | 실제 화면 크기 px (상태바·내비게이션 바 포함, `getRealSize`)                                                                        |
| `screen.hash`                   |      | 앱이 계산한 화면 지문. 지금은 서버가 쓰지 않습니다                                                                                  |
| `screen.nodes`                  | ✅   | 최대 **60개**                                                                                                                       |
| `deviceId`                      |      | (dev 디버그용) 디버그 뷰어에 쓰는 기기 ID. 이 기기 아래에 요청·AI 판단이 기록됩니다. 서버 응답에는 영향 없고, prod에서는 무시합니다 |

### 노드 형식 (디버그 뷰어 `POST /v1/dev/screens`와 같음)

| 필드                                                         | 뜻                                                                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `i`                                                          | 요소 번호 (0 이상 정수, 화면 안에서 유일)                                                         |
| `t`                                                          | text (100자까지)                                                                                  |
| `d`                                                          | contentDescription (100자까지)                                                                    |
| `c`                                                          | 클래스 이름 (100자까지). 서버가 끝부분만 씁니다 (`android.widget.Button` → `Button`)              |
| `b`                                                          | `getBoundsInScreen()`의 `[left, top, right, bottom]`, 화면 절대 좌표 px                           |
| `clickable`, `editable`, `scrollable`, `checked`, `selected` | `true`일 때만 넣습니다. 서버가 모델에 상태로 전달해, 누를 수 있는 요소·입력 칸을 고르는 데 씁니다 |

> 지침서 5.7의 예시(`"c": 1`, `b`가 10% 단위)는 쓰지 않습니다. 고령자 앱이 디버그 뷰어와 같은 직렬화 코드를 쓰는 것으로 합의했습니다.

- 입력 칸(`editable`)에 적힌 글자는 보내지 않습니다 (앱이 이미 거름).
- 서버는 받은 글자에서 전화·계좌·카드번호·주민번호·금액(`1,000원`, 원 없이 쉼표로 묶인 `1,234,567` 포함)을 `***`로 가린 뒤 모델에 보냅니다. 받는 분 이름 같은 글자는 가리지 않으니, 은행 화면이라도 앱이 보낼 노드를 줄일 수 있으면 좋습니다.

## 3. 응답

항상 **200**입니다. 모델 실패·거절·시간 초과도 200 + `type: "say"`로 옵니다. 앱은 `type`에 따라 처리합니다.

```json
{
  "requestId": 108,
  "type": "highlight",
  "say": "화면 왼쪽 가운데의 '카카오톡'을 누르세요.",
  "target": 0,
  "targetText": "카카오톡"
}
```

| `type`      | 함께 오는 필드                                       | 앱 동작                                     |
| ----------- | ---------------------------------------------------- | ------------------------------------------- |
| `highlight` | `target`, `targetText`                               | `target` 요소에 빨간 테두리 + `say` 읽기    |
| `suggest`   | `target`, `targetText`, `chips` (0~4개, 각 30자까지) | 입력 칸(`target`) 표시 + 자동완성 단추      |
| `swipe`     | `dir`: `up` / `down` / `left` / `right`, `seekText`  | 밀기 화살표. `dir`은 **손가락을 미는 방향** |
| `ask`       |                                                      | 질문을 읽고 대답을 기다림                   |
| `say`       |                                                      | 말만 전달 (누를 것 없음)                    |
| `done`      |                                                      | 안내 종료                                   |

- `say`는 항상 옵니다. 존댓말, **60자 이내**입니다 (넘으면 서버가 자르고 `…`을 붙임).
- 쓰지 않는 필드는 응답에 없습니다 (null로 오지 않음).
- `cached: true`: 응답 캐시(7장)에서 꺼낸 답일 때만 붙습니다. 모델이 새로 답했으면 빠집니다. 앱 동작은 같습니다.
- `target`은 **요청에 있던 `i` 중 하나**임을 서버가 보장합니다. 없는 번호를 모델이 내면 서버가 `say`로 낮춥니다.
- `targetText`: `target` 요소의 글자(`t`, 없으면 `d`, 숫자 개인정보는 가림, 100자까지). 요소 자체에 글자가 없으면 **그 요소 영역 안에 든 글자 요소 중 위쪽·왼쪽 것**을 씁니다 (설정 화면 한 줄처럼 눌리는 틀 안에 제목이 있는 경우: 틀 → 제목 "Display"). 그래도 없으면 빠집니다. 스크롤로 요소 번호가 바뀌어도 앱이 같은 요소를 다시 찾을 때 쓸 수 있습니다.
- `seekText` (`swipe`만): 밀어서 찾으려는 요소의 글자 (예: "디스플레이"). 모델이 무엇을 찾는지 모르면 빠집니다. 밀다가 이 글자가 화면에 나타나면 앱이 서버를 다시 부르지 않고 바로 "누르세요" 안내로 바꿀 수 있습니다.

### 서버가 대신 보내는 문장

| 상황                                                       | `type` | `say`                                                    |
| ---------------------------------------------------------- | ------ | -------------------------------------------------------- |
| 모델 오류·시간 초과 (8.5초)                                | `say`  | 서버가 잠시 바빠요. 조금 뒤에 다시 말씀해 주세요.        |
| 모델 거절, 형식 오류, 화면에 없는 `target`                 | `say`  | 제가 화면을 잘 못 알아봤어요. 다시 말씀해 주시겠어요?    |
| 비밀번호·인증번호 화면                                     | `say`  | 이 화면은 직접 입력해 주세요. 제가 대신 보지 않을게요.   |
| `nodes`가 0개 (시스템 창만 떠 있는 등, 모델을 부르지 않음) | `say`  | 지금 화면을 읽지 못했어요. 잠시 뒤에 다시 말씀해 주세요. |

앱은 이 문장들을 그대로 읽으면 됩니다. "서버가 바빠요"일 때는 로컬 플래너 안내를 유지하는 게 낫습니다.

### 오류 (200이 아닌 경우)

| HTTP | reason              | 언제                                                 |
| ---- | ------------------- | ---------------------------------------------------- |
| 400  | `invalid-argument`  | 본문 형식 오류 (노드 60개 초과, `requestId` 없음 등) |
| 401  | (API Gateway 형식)  | 토큰 없음·만료                                       |
| 403  | `profile-required`  | `POST /v1/users/me` 등록 전 → 등록 후 1번 재시도     |
| 403  | `permission-denied` | role 이 elder 가 아님                                |

이 경우 앱은 로컬 플래너로 계속합니다. 호출 한도는 시연 단계라 두지 않습니다 (나중에 생기면 `429 rate-limited`).

## 4. 서버가 지키는 것

| 항목      | 내용                                                                                                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 거부 규칙 | **모델을 부르지 않음**: 글자·설명에 `비밀번호`, `패스워드`, `password`, `암호`, `인증번호`, `OTP`, `보안카드`, `CVC`, `CVV`, `PIN`, `핀번호`, `주민등록번호`가 있는 화면    |
| 마스킹    | 모델에 보내기 전에, 그리고 모델의 `say`·`chips`에서도 숫자 개인정보를 가림. 가려진 값이 든 chip은 뺌                                                                        |
| 지시 무시 | 화면 글자 안의 지시("이 버튼을 누르세요" 같은 광고·피싱 문구)는 따르지 않도록 프롬프트에 명시                                                                               |
| 확정 버튼 | 송금·결제·대출·본인인증을 확정하는 버튼은 누르라고 하지 않고 `say`로 "받는 분·금액을 직접 확인하고 누르세요" 안내. 화면의 금액·계좌·잔액·받는 분 이름은 `say`에 옮기지 않음 |
| 역할      | role=elder 만 호출 가능                                                                                                                                                     |
| 로그      | 화면 요소는 남기지 않음. 프롬프트 버전, 목표, 패키지, 노드 수, 결과 종류, 지연, 토큰만 기록                                                                                 |

## 5. 앱에서 할 일 (지침서 3장)

1. 요청마다 `requestId`를 올리고, 요청할 때의 **화면 지문**을 기억합니다.
2. 응답이 오면 아래 중 하나라도 해당하면 **버립니다**.
   - `requestId`가 최신이 아님
   - 지금 화면 지문이 요청 때와 다름
   - `target`이 지금 화면에 없음 (번호가 같아도 `targetText`가 다르면 다른 요소로 봄)
3. 응답이 **9초**를 넘기면 버리고 로컬 안내를 유지합니다. 서버 모델 타임아웃은 8.5초입니다.

## 7. 응답 캐시 (S6)

같은 어르신이 **같은 화면에서 같은 요청**을 다시 하면 모델을 부르지 않고 저장된 답을 돌려줍니다 (토큰 절약, 응답도 빠름).

| 항목    | 내용                                                                                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 키      | SHA-256( 프롬프트 버전 · 모델 · 화면 지문 버전(`fp@v1`) · **uid** · 서버 화면 지문 · `goal` · `slots` · 띄어쓰기를 뺀 `utterance` )                        |
| 범위    | **어르신별**. 화면에 연락처 이름·검색어 같은 개인 글자가 섞이므로 다른 어르신과 나누지 않습니다                                                            |
| 빼는 것 | `requestId`, `history`, `deviceId`. 화면 지문은 숫자를 `#`으로 바꾸고 위치를 10칸으로 묶어 시계·재생 시간에 흔들리지 않습니다 (`src/cache/fingerprint.ts`) |
| 저장    | 모델이 정상 답하고 후처리에서 낮춰지지 않은 답만. 대체 문장(바빠요·못 알아봤어요 등)은 저장하지 않음                                                       |
| 꺼낼 때 | 저장된 `target`이 지금 화면에서 **같은 글자**의 요소인지 다시 확인. 번호가 바뀌었으면 `targetText`로 다시 찾고, 없으면 모델을 부릅니다                     |
| 순서    | 빈 화면·비밀번호 화면 거부 → **캐시 조회** → 마스킹 → 모델 → 후처리 → **캐시 저장**                                                                        |
| 수명    | 7일 (DynamoDB TTL). 프롬프트·모델·지문 규칙이 바뀌면 키가 저절로 갈립니다                                                                                  |
| 저장소  | `haebom-<env>-ai-cache` (`key`, `response`, `savedAt`, `ttl`). 화면 요소 원문은 저장하지 않음 (키는 해시, `say`·`targetText`는 마스킹된 값)                |
| 고장    | 캐시를 읽거나 쓰지 못해도 응답에는 영향 없음 (모델을 부름, 경고 로그만)                                                                                    |

로그 `guide completed`에 `cache: "hit" | "miss"`가 붙고, 디버그 뷰어 기록(`ai.cache`)에도 남습니다.

## 6. 검토 결과와 개선 예정

### 지금 성능 (dev, 2026-11-26)

| 항목      | 값                                                                           |
| --------- | ---------------------------------------------------------------------------- |
| 모델      | `claude-sonnet-5-5`, thinking 끔(`between_tools`), effort `low`, 구조화 출력 |
| 응답 시간 | 1.6~6.5초 (3건, 노드 4개. 표본이 작아 앱 연동 후 다시 측정)                  |
| 토큰      | 입력 약 250 + 캐시 1,844 (시스템 프롬프트 캐싱 동작), 출력 약 60             |

### 검토 반영 (2026-11-26, `guide@v2`·`guide@v3`)

| #   | 내용                                                                                                             | 앱 영향                                             |
| --- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 1   | 노드 상태(`clickable`, `editable` 등)를 모델에 전달하고, 프롬프트에 "누를 수 있는 요소·입력 칸을 고르라"고 명시  | 없음 (이미 보내고 있음)                             |
| 2   | ⚠️ role=elder 검사. 호출 한도는 시연 단계라 두지 않음                                                            | **#2 등록 후 호출해야 함** (403 처리)               |
| 3   | 비밀번호 화면 판별 단어 추가 (`암호`, `PIN`, `핀번호`, `주민등록번호` 등)                                        | 없음                                                |
