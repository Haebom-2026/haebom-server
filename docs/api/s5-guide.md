# S5 API: 화면 안내 (#16 guide)

- 작성일: 2026-11-26
- 대상: 고령자 앱
- 상태: **`guide@v4.8` dev 배포 완료**. v3 응답과 호환되고 필드만 늘었습니다 (7장)
- 기준: 지침서 3장·5.7, [서버 기획](../server-plan.md) 5.1·5.3, 고령자 앱 검토 답변 4.2 (노드 형식)

어르신이 말한 일과 지금 화면의 접근성 요소를 보내면, **다음에 할 행동 하나**를 돌려줍니다. 서버는 Claude Sonnet 5.5로 판단하고, 모델 출력을 지금 화면에 맞는지 다시 확인한 뒤 응답합니다.

공통 규칙(Base URL, 인증, 오류 형식)은 [S1 문서 1장](s1-users-links.md#1-공통)과 같습니다.

> **먼저 `POST /v1/users/me`로 `role: "elder"` 등록이 필요합니다.** 등록하지 않은 토큰이나 보호자 토큰으로 부르면 403입니다.

---

## 1. 언제 부르나

- **로컬 플래너가 처리하지 못하는 일**일 때만 부릅니다. 연락처 추가, 유튜브 검색, 정부24, 앱 열기처럼 앱이 아는 일은 앱이 직접 안내합니다.
- 명령 하나에 **여러 번** 부를 수 있습니다. 화면이 바뀌어 다음 단계를 정해야 할 때마다 부릅니다.
- **부르지 않는 경우**: 비밀번호·인증번호 입력 칸이 있는 화면. 서버도 한 번 더 거르지만(4장), 앱에서 먼저 보내지 않는 게 원칙입니다.
- **은행·금융 앱도 안내합니다.** 민감하다는 표시(L1 "보호자에게 알릴까요?" 팝업, L2 승인)는 지침서 4장대로 **명령 단계에서 앱이 먼저** 띄우고, 그다음 화면 안내에 guide를 씁니다. 송금 확정 버튼은 서버가 누르라고 하지 않고 본인이 확인하도록 안내합니다.
  - ⚠️ 고령자 앱은 지금 은행 패키지(`bank`·`kbstar`·`toss`·`shinhan`·`wooribank`) 화면을 보내지 않으니, 이 필터를 **guide 요청에서는 풀어야** 합니다. 디버그 뷰어 전송에서는 그대로 두는 걸 권합니다.

- **응답을 기다리지 않습니다.** 자막에 "잠깐만요, 살펴보고 있어요"만 띄우고 화면을 막지 않습니다 (지침서 3.4).

## 2. 요청

```
POST /v1/elder/guide
Authorization: Bearer <Firebase ID 토큰>
Content-Type: application/json; charset=utf-8
```

```json
{
  "requestId": 108,
  "goal": "OPEN_APP",
  "utterance": "카카오톡 열어 줘",
  "slots": { "app": "카카오톡" },
  "history": ["홈 화면으로 가세요."],
  "screen": {
    "pkg": "com.sec.android.app.launcher",
    "width": 1080,
    "height": 2640,
    "nodes": [
      {
        "i": 0,
        "t": "카카오톡",
        "c": "android.widget.TextView",
        "b": [60, 1500, 300, 1760],
        "clickable": true
      },
      {
        "i": 1,
        "d": "앱스",
        "c": "android.widget.ImageView",
        "b": [440, 2300, 640, 2500],
        "clickable": true
      }
    ]
  }
}
```

| 필드                            | 필수 | 규칙                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestId`                     | ✅   | 0 이상 정수. 서버가 그대로 돌려줍니다 (늦은 응답 버리기용)                                                                                                                                                                                                                                                                                                 |
| `goal`                          | ✅   | 1~40자. 앱 IntentParser의 목표: `ADD_CONTACT`, `YOUTUBE`, `GOV24`, `BANK`, `OPEN_APP`, `UNKNOWN`                                                                                                                                                                                                                                                           |
| `utterance`                     |      | 어르신이 한 말 (200자까지)                                                                                                                                                                                                                                                                                                                                 |
| `slots`                         |      | 말에서 뽑은 값. 키 40자, 값 100자까지 (예: `app`, `query`, `name`, `phone`)                                                                                                                                                                                                                                                                                |
| `history`                       |      | 지금까지 안내한 문장, 오래된 것부터 최대 10개 (각 200자). 대답은 `"어르신 답: 네"`, `"가족 답: 있어요"`처럼 넣어 주세요                                                                                                                                                                                                                                    |
| `userReply`                     |      | (v4) 바로 앞 `ask`에 어르신이 고른 답 (100자까지). `"모르겠어요"`, `"가족 답: …"`, `"가족도 모름"` 포함                                                                                                                                                                                                                                                    |
| `mode`                          |      | (v4) `guide`(기본): 말로 이끌어 드림. `solo`: 어르신이 혼자 하다가 막힐 때 보는 힌트                                                                                                                                                                                                                                                                       |
| `screen.pkg`                    | ✅   | 지금 화면의 앱 패키지                                                                                                                                                                                                                                                                                                                                      |
| `screen.width`, `screen.height` | ✅   | 실제 화면 크기 px (상태바·내비게이션 바 포함, `getRealSize`)                                                                                                                                                                                                                                                                                               |
| `screen.hash`                   |      | 앱이 계산한 화면 지문. 지금은 서버가 쓰지 않습니다                                                                                                                                                                                                                                                                                                         |
| `screen.nodes`                  | ✅   | 최대 **60개**                                                                                                                                                                                                                                                                                                                                              |
| `deviceId`                      |      | (dev 디버그용) 디버그 뷰어에 쓰는 기기 ID. 이 기기 아래에 요청·AI 판단이 기록됩니다. 서버 응답에는 영향 없고, prod에서는 무시합니다                                                                                                                                                                                                                        |
| `commandId`                     |      | (선택, R3) classify의 명령 번호. dev에서 명령 단계를 기록해 지도 학습 재료로 씁니다 ([jev 기획](../jev-routing-plan.md) 3.6·6장)                                                                                                                                                                                                                           |
| `lastAction`                    |      | (선택, R3) 바로 앞 화면에서 어르신이 **실제로** 한 행동 `{ stepId?, seq, action, text }`. `stepId`: 그 화면에서 받은 안내의 id(따랐으면), `seq`: 명령 안 행동 순번(0부터, 빠지면 그 구간은 학습 안 함), `action`: `tap` `type` `swipe_up/down/left/right` `back` `home` `other`, `text`: 누른 요소의 글자(서버가 가림, `type`이면 넣은 값은 저장하지 않음) |

### 노드 형식 (디버그 뷰어 `POST /v1/dev/screens`와 같음)

| 필드                                                                    | 뜻                                                                                                                                                                |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `i`                                                                     | 요소 번호 (0 이상 정수, 화면 안에서 유일)                                                                                                                         |
| `t`                                                                     | text (100자까지)                                                                                                                                                  |
| `d`                                                                     | contentDescription (100자까지)                                                                                                                                    |
| `c`                                                                     | 클래스 이름 (100자까지). 서버가 끝부분만 씁니다 (`android.widget.Button` → `Button`)                                                                              |
| `b`                                                                     | `getBoundsInScreen()`의 `[left, top, right, bottom]`, 화면 절대 좌표 px                                                                                           |
| `clickable`, `editable`, `scrollable`, `checked`, `selected`, `focused` | `true`일 때만 넣습니다. 서버가 모델에 상태로 전달해, 누를 수 있는 요소·입력 칸을 고르는 데 씁니다                                                                 |
| `enabled`                                                               | `false`일 때만 의미가 있습니다. 서버가 `disabled`(회색이라 아직 누를 수 없음)로 전달합니다                                                                        |
| `secret`                                                                | (v4.5) 비밀 칸(비밀번호·인증번호·계좌번호 등)이면 `true`. 이 칸은 `t`·`d` 없이 보냅니다 (서버도 받자마자 지움)                                                    |
| `filled`                                                                | (v4.6) 입력 칸에 무언가 적혀 있으면 `true` (비밀 칸 포함). **내용은 보내지 않습니다.** 서버가 `filled` 상태로 전달해, 채워진 칸은 넘어가고 다음 단계를 안내합니다 |

> 지침서 5.7의 예시(`"c": 1`, `b`가 10% 단위)는 쓰지 않습니다. 고령자 앱이 디버그 뷰어와 같은 직렬화 코드를 쓰는 것으로 합의했습니다.

- 입력 칸(`editable`)에 적힌 글자는 보내지 않습니다 (앱이 이미 거름).
- 서버는 받은 글자에서 전화·계좌·카드번호·주민번호·금액(`1,000원`, 원 없이 쉼표로 묶인 `1,234,567` 포함)을 `***`로 가린 뒤 모델에 보냅니다. 받는 분 이름 같은 글자는 가리지 않으니, 은행 화면이라도 앱이 보낼 노드를 줄일 수 있으면 좋습니다.

## 3. 응답

항상 **200**입니다. 모델 실패·거절·시간 초과도 200 + `type: "say"`로 옵니다. 앱은 `type`에 따라 처리합니다.

```json
{
  "requestId": 108,
  "type": "highlight",
  "say": "화면 왼쪽 가운데의 '카카오톡'을 누르세요.",
  "target": 0,
  "targetText": "카카오톡"
}
```

| `type`      | 함께 오는 필드                                                  | 앱 동작                                                                                |
| ----------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `highlight` | `target`, `targetText`                                          | `target` 요소에 빨간 테두리 + `say` 읽기                                               |
| `suggest`   | `target`, `targetText`, `chips` (0~1개), `typeText`?            | 입력 칸(`target`) 표시. `typeText`가 있으면 칸 아래 **"넣기"** 버튼 → 누르면 입력      |
| `swipe`     | `dir`: `up` / `down` / `left` / `right`, `target`?, `seekText`? | 밀기 화살표. `dir`은 **손가락을 미는 방향**. `target`이 있으면 그 자리에 화살표        |
| `ask`       | `options`? (최대 4개), `fact`?                                  | 질문을 읽고 `options`를 큰 버튼으로 + "모르겠어요" 버튼. 고른 답을 `userReply`로 (6장) |
| `say`       | `nav`? (`home` / `back`)                                        | 말만 전달. `nav`가 있으면 홈·뒤로 버튼 위치를 표시                                     |
| `done`      |                                                                 | 안내 종료                                                                              |

#### v4에서 늘어난 필드 (모두 선택, 없으면 v3와 같게 처리)

| 필드       | 언제                | 뜻                                                                                                                                                                                                      |
| ---------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`   | 모델이 답할 때 항상 | `in_progress` 계속, `clarify` 여쭤봄(`ask`), `off_track` 예상과 다른 화면이라 되돌아가는 중, `stopped` 여기서 멈춤(가족 확인·3번 실패·가짜 사이트), `done` 끝남. 서버가 대신 답한 문장(4장 표)에는 없음 |
| `typeText` | `suggest`           | 칸에 넣을 글자 (예: "화면 자동 꺼짐"). 어르신만 아는 값이나 비밀 칸이면 없음 → "직접 써 주세요" 안내                                                                                                    |
| `options`  | `ask`               | 답 버튼 글자 (예: `["네", "아니요"]`, `["11월 28일", "12월 5일"]`)                                                                                                                                      |
| `fact`     | `ask`               | `site_membership` 가입 여부, `login_method` 로그인 방법, `has_certificate` 인증서 여부. 가족에게 물어볼 수 있는 질문이라는 표시 (가족에게 묻는 API는 아직 없음, 6장)                                    |
| `nav`      | `say`               | `home` 홈 화면으로, `back` 뒤로                                                                                                                                                                         |

`stopped`는 `type: "say"`로 옵니다. 송금·결제·설치·권한 허용 확정 단계, 공식 주소가 아닌 사이트, 같은 단계 3번 실패일 때입니다.

- `say`는 항상 옵니다. 존댓말 한 문장, **80자 이내**입니다 (넘으면 서버가 자르고 `…`을 붙임). v4는 "넣기" 안내처럼 조금 길어질 수 있어 60자에서 늘렸습니다.
- 쓰지 않는 필드는 응답에 없습니다 (null로 오지 않음).
- `target`은 **요청에 있던 `i` 중 하나**임을 서버가 보장합니다. 없는 번호를 모델이 내면 서버가 `say`로 낮춥니다.
- `targetText`: `target` 요소의 글자(`t`, 없으면 `d`, 숫자 개인정보는 가림, 100자까지). 요소 자체에 글자가 없으면 **그 요소 영역 안에 든 글자 요소 중 위쪽·왼쪽 것**을 씁니다 (설정 화면 한 줄처럼 눌리는 틀 안에 제목이 있는 경우: 틀 → 제목 "Display"). 그래도 없으면 빠집니다. 스크롤로 요소 번호가 바뀌어도 앱이 같은 요소를 다시 찾을 때 쓸 수 있습니다.
- `seekText` (`swipe`만): 밀어서 찾으려는 요소의 글자 (예: "디스플레이"). 모델이 무엇을 찾는지 모르면 빠집니다. 밀다가 이 글자가 화면에 나타나면 앱이 서버를 다시 부르지 않고 바로 "누르세요" 안내로 바꿀 수 있습니다.

### 서버가 대신 보내는 문장

| 상황                                                       | `type` | `say`                                                    |
| ---------------------------------------------------------- | ------ | -------------------------------------------------------- |
| 모델 오류·시간 초과 (8.5초)                                | `say`  | 서버가 잠시 바빠요. 조금 뒤에 다시 말씀해 주세요.        |
| 모델 거절, 형식 오류, 화면에 없는 `target`                 | `say`  | 제가 화면을 잘 못 알아봤어요. 다시 말씀해 주시겠어요?    |
| 비밀번호·인증번호 화면                                     | `say`  | 이 화면은 직접 입력해 주세요. 제가 대신 보지 않을게요.   |
| `nodes`가 0개 (시스템 창만 떠 있는 등, 모델을 부르지 않음) | `say`  | 지금 화면을 읽지 못했어요. 잠시 뒤에 다시 말씀해 주세요. |

앱은 이 문장들을 그대로 읽으면 됩니다. "서버가 바빠요"일 때는 로컬 플래너 안내를 유지하는 게 낫습니다.

### 오류 (200이 아닌 경우)

| HTTP | reason              | 언제                                                 |
| ---- | ------------------- | ---------------------------------------------------- |
| 400  | `invalid-argument`  | 본문 형식 오류 (노드 60개 초과, `requestId` 없음 등) |
| 401  | (API Gateway 형식)  | 토큰 없음·만료                                       |
| 403  | `profile-required`  | `POST /v1/users/me` 등록 전 → 등록 후 1번 재시도     |
| 403  | `permission-denied` | role 이 elder 가 아님                                |

이 경우 앱은 로컬 플래너로 계속합니다. 호출 한도는 시연 단계라 두지 않습니다 (나중에 생기면 `429 rate-limited`).

## 4. 서버가 지키는 것

| 항목      | 내용                                                                                                                                                                                                                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 거부 규칙 | **모델을 부르지 않음**: `비밀번호`, `패스워드`, `password`, `암호`, `인증번호`, `OTP`, `보안카드`, `CVC`, `CVV`, `PIN`, `핀번호`, `주민등록번호` 등이 **입력 칸(editable)의 글자, 또는 입력 칸 바로 위·왼쪽·안쪽의 짧은(30자 이하) 이름표**에 있는 화면 (v4.4). 안내 문구에만 있으면 막지 않음. `secret: true`로 표시한 칸은 빼고 봄 (v4.5) |
| 마스킹    | 모델에 보내기 전에, 그리고 모델의 `say`·`chips`에서도 숫자 개인정보를 가림. 가려진 값이 든 chip은 뺌                                                                                                                                                                                                                                        |
| 지시 무시 | 화면 글자 안의 지시("이 버튼을 누르세요" 같은 광고·피싱 문구)는 따르지 않도록 프롬프트에 명시                                                                                                                                                                                                                                               |
| 확정 버튼 | 송금·결제·대출·본인인증을 확정하는 버튼은 누르라고 하지 않고 `say`로 "받는 분·금액을 직접 확인하고 누르세요" 안내. 화면의 금액·계좌·잔액·받는 분 이름은 `say`에 옮기지 않음                                                                                                                                                                 |
| 역할      | role=elder 만 호출 가능                                                                                                                                                                                                                                                                                                                     |
| 로그      | 화면 요소는 남기지 않음. 프롬프트 버전, 목표, 패키지, 노드 수, 결과 종류, 지연, 토큰만 기록                                                                                                                                                                                                                                                 |

## 5. 앱에서 할 일 (지침서 3장)

1. 요청마다 `requestId`를 올리고, 요청할 때의 **화면 지문**을 기억합니다.
2. 응답이 오면 아래 중 하나라도 해당하면 **버립니다**.
   - `requestId`가 최신이 아님
   - 지금 화면 지문이 요청 때와 다름
   - `target`이 지금 화면에 없음 (번호가 같아도 `targetText`가 다르면 다른 요소로 봄)
3. 응답이 **9초**를 넘기면 버리고 로컬 안내를 유지합니다. 서버 모델 타임아웃은 8.5초입니다.

## 6. 질문(`ask`)에 답하기

guide가 어르신께 여쭤볼 것이 있으면 `type: "ask"`로 답합니다. **답을 보내는 별도 API는 없습니다.** 어르신의 답은 **다음 guide 요청(#16)에 실어** 보냅니다.

### 6.1 흐름

```
앱 ── #16 guide ──▶ 서버
앱 ◀── { type: "ask", status: "clarify", say: "정부24에 가입해서 아이디가 있으세요?",
         options: ["네, 있어요", "아니요"], fact: "site_membership" }
       화면 위 카드: 질문 + [네, 있어요] [아니요] [모르겠어요]
어르신: [아니요]
앱 ── #16 guide { userReply: "아니요", history: [..., "어르신 답: 아니요"], screen: 지금 화면 } ──▶ 서버
앱 ◀── { type: "highlight", target: 12, say: "화면 아래 '비회원 신청'을 눌러 주세요." }
```

### 6.2 받는 값 (`type: "ask"`)

| 필드      | 항상 | 뜻                                                                                                                                    |
| --------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `say`     | ✅   | 질문 (80자까지). 읽어 드립니다                                                                                                        |
| `status`  | ✅   | `"clarify"`                                                                                                                           |
| `options` |      | 답 버튼 글자, 1~4개 (각 12자까지). **없으면 열린 질문**(앱 이름, 검색어 등) → 말로 답받기                                             |
| `fact`    |      | `site_membership`(가입했는지), `login_method`(로그인 방법), `has_certificate`(인증서가 있는지). 가족에게 물을 수 있는 질문이라는 표시 |

- `target`이 없습니다. 질문하는 동안에는 화면의 아무것도 가리키지 않습니다.
- "모르겠어요"는 서버가 넣지 않습니다. **앱이 항상 덧붙입니다.**

### 6.3 보내는 값 (다음 #16 요청)

| 필드        | 넣는 값                                                                                                                 |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| `userReply` | 고른 버튼 글자 그대로 (예: `"아니요"`), 말로 답했으면 음성 인식 문장 (100자까지). **바로 다음 요청에 한 번만** 넣습니다 |
| `history`   | 끝에 `"어르신 답: 아니요"`를 더합니다 (최대 10개, 오래된 것부터 버림). 같은 질문을 다시 하지 않게 하는 기록입니다       |
| `utterance` | 처음 명령 그대로. 지금처럼 `"… / 아니요"`를 붙여도 됩니다                                                               |
| `requestId` | 새 번호 (늘 하던 대로)                                                                                                  |
| `screen`    | **지금 화면.** 답을 들은 화면을 다시 보내야 서버가 그 화면의 버튼을 가리킬 수 있습니다                                  |

### 6.4 특별한 답

| `userReply`                     | 서버 동작                                                                                 |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| `"모르겠어요"`                  | 같은 질문을 다시 하지 않고, 화면에서 직접 고르시게 안내                                   |
| 전화번호를 말로 답함            | 번호를 가린 자리표시로 AI에 보내고, 번호 칸이면 `typeText`로 넣어 드림 (7장 `guide@v4.3`) |
| `"가족 답: …"`, `"가족도 모름"` | 서버는 받아들이지만, 가족에게 묻는 API가 아직 없어서 지금은 보낼 일이 없습니다            |

### 6.5 서버가 질문하는 경우

| 경우                               | 예                                        | `options`                                   |
| ---------------------------------- | ----------------------------------------- | ------------------------------------------- |
| 어느 앱·누구인지 정말 모를 때      | "친구 추가" → 전화번호부인지 카카오톡인지 | `["전화번호부", "카카오톡"]`                |
| 어르신 본인만 아는 선택            | 회원/비회원, 인증 방법, 받는 방법         | 화면의 선택지에 맞춤                        |
| 날짜가 두 가지로 읽힐 때           | "다음 주 토요일"                          | `["11월 28일", "12월 5일"]`                 |
| 시각이 넓을 때                     | "오전에"                                  | `["8시쯤", "9시쯤", "10시쯤", "아무 때나"]` |
| 미리 채워진 값을 꼭 확인해야 할 때 | 주민등록상 주소가 지금 주소와 같은지      | `["네", "아니요"]`                          |
| 하려는 일이 열려 있을 때           | "설치해 줘"(앱 이름 없음), "찾아 봐"      | 없음 (말로 답함)                            |

묻지 않는 경우: 하려는 일이 분명할 때, 선택지가 3개보다 많을 때(화면에서 직접 고르게 함), 이미 답한 것(`utterance`·`history`·`userReply`에 있음).

### 6.6 앱이 정할 것

- 질문 카드에서 **답 없이 새 명령**을 하시면, 그 명령으로 처음부터 다시 시작합니다 (`userReply` 없이)
- 답을 기다리는 시간과, 오래 답이 없을 때 어떻게 할지는 앱이 정합니다 (서버는 기다리지 않음)

### `guide@v4.3` (2026-11-26): 어르신이 말한 전화번호 넣어 드리기

연락처 추가에서 어르신이 말한 번호가 `***`로 가려져, 번호 칸에 "넣기"를 줄 수 없던 문제를 고쳤습니다.

1. 서버가 어르신이 **직접 말한** 글자(`utterance`, `slots`, `history`, `userReply`)의 전화번호를 `[번호1]` 같은 자리표시로 바꿔 AI에 보냅니다. 하이픈·점·띄어쓰기·붙여 쓴 번호, 지역번호 모두.
2. AI가 번호 칸에 `typeText: "[번호1]"`을 쓰면, 서버가 **번호 칸일 때만** 원래 번호로 되돌려 `typeText`·`chips`에 넣습니다. 번호 칸 판단: 가리킨 칸의 글자(`전화`, `번호`, `휴대`, `연락처` …), 칸에 글자가 없으면 `slots.state`(예: `"입력 중: 전화번호"`).
3. 번호 칸이 아니거나 자리표시를 알아볼 수 없으면 `typeText`를 빼서 어르신이 직접 쓰시게 합니다 (잘못된 칸에 번호가 들어가지 않게).
4. 안내 말의 자리표시는 "말씀하신 번호"로 바꿉니다.

**진짜 번호는 앱에 보내는 응답에만 있습니다.** AI 입력은 `[번호1]`, 디버그 기록은 요청·응답 모두 `***`, 로그에는 남지 않습니다. 화면에 보이는 번호(최근 통화 등)는 지금처럼 `***`로 가립니다.

띄어쓰기·점으로 끊긴 10자리 이상 번호(`010 1234 5678`)도 이제 마스킹됩니다 (전에는 그대로 AI에 감).

dev 시험 (실제 폰 연락처 화면 3개 + 시험 번호, 시나리오 5개 × 2회, 10/10):

| 시나리오                              | 결과                                            |
| ------------------------------------- | ----------------------------------------------- |
| 번호 칸 입력 중 + `010-1234-5678`     | `suggest` 번호 칸, `typeText: "010-1234-5678"`  |
| 번호 칸 + `010 1234 5678` (띄어 말함) | `typeText: "010 1234 5678"`                     |
| 이름 칸 입력 중 + 번호                | 이름 칸에 `김민정` (번호를 이름 칸에 넣지 않음) |
| 번호 칸 + 번호를 아직 말하지 않음     | `typeText` 없이 "번호를 직접 써 주세요"         |
| 이름을 다 쓴 화면 + 번호              | 전화번호 칸으로 이동해 번호 넣기                |

한계: 음성 인식이 번호를 한글("공일공 일이삼사…")로 주면 알아보지 못합니다. 그때는 v4.2처럼 직접 쓰시게 안내합니다.

### `guide@v4.5` (2026-11-27): 로그인 화면도 안내 (비밀 칸 표시)

지금까지는 비밀번호·인증번호 칸이 하나라도 있으면 화면 전체를 AI에 보내지 않아, 로그인 화면은 앱 규칙으로만 안내했습니다. 이제 앱이 그런 칸을 **비밀 칸으로 표시**해 보내면, 서버 AI가 나머지 화면(아이디 칸, 로그인·회원가입·간편 로그인 버튼)을 안내하고 그 칸만 직접 입력하시게 합니다.

**앱이 보낼 것**: 비밀 칸을 `{ "i": 3, "c": "…EditText", "b": [...], "editable": true, "secret": true }`처럼 `t`·`d` 없이. 판단은 `AccessibilityNodeInfo.isPassword()`를 우선하고, 인증번호·계좌번호·주민번호 칸은 이름표로 판단하는 걸 권합니다. 칸 옆의 이름표("비밀번호")는 그대로 보내도 됩니다.

**서버가 하는 것**

1. 비밀 칸에 글자가 따라와도 받자마자 지웁니다. AI·디버그 기록·로그 어디에도 남지 않습니다.
2. 비밀 칸은 비밀번호 화면 판정(4장)에서 빼고, 화면을 AI에 보냅니다. 표시가 없는 비밀번호 칸이 있으면 지금처럼 거부합니다.
3. AI에는 `secret` 상태로 알려 "그 칸은 직접 입력해 주세요"(`status: "in_progress"`)로 안내하게 합니다.
4. 비밀 칸을 가리키는 응답은 `suggest` + `target`(그 칸) + `chips: []`이고, **`typeText`는 AI가 무엇을 내든 서버가 빼서 보냅니다.**

앱이 `secret`을 보내지 않으면 지금과 똑같이 동작합니다.

### `guide@v4.6` (2026-11-27): 입력 칸 채워짐(`filled`) 표시

v4.5에서는 비밀 칸의 글자를 모두 지워서, 어르신이 비밀번호를 넣으셨는지 AI가 알 수 없었습니다. 이제 앱이 **내용 없이 "채워졌다"는 사실만** `"filled": true`로 보내면, 서버가 지우지 않고 AI에 전달합니다.

```json
{ "i": 3, "c": "EditText", "editable": true, "secret": true, "filled": true }
```

- 비밀 칸뿐 아니라 아이디 같은 다른 입력 칸에도 똑같이 씁니다. 지금 앱이 붙이는 `"t": "(입력되어 있음)"` 대신 쓰면 됩니다 (비밀 칸의 `t`는 서버가 지우므로 그 표시는 AI에 가지 않습니다).
- 앱 판단 방법: 비밀번호 칸은 글자를 읽을 수 없어도 힌트가 보이는지(`isShowingHintText()`)나 글자 길이로 비었는지 알 수 있습니다.
- AI는 `filled`인 칸을 넘어가고 빈 칸부터 안내합니다. 필요한 칸이 모두 차 있으면 "다 쓰셨으면 '로그인'을 눌러 주세요"처럼 다음 버튼으로 넘어갑니다.
- 한계: "찼다"는 것만 알고 끝까지 다 쳤는지는 모릅니다. 그래서 "다 쓰셨으면"이라고 말하고, 비밀번호가 틀리면 다음 화면(오류)을 보고 안내합니다.
- 앱이 `filled`를 보내지 않으면 지금과 똑같이 동작합니다.
- 함께 고친 것: 안내 말에서 **색을 말하지 않습니다.** 서버는 화면 요소의 색을 받지 않는데, AI가 같은 버튼을 "초록색", "파란"으로 지어내는 것을 dev 시험에서 확인했습니다. 위치와 모양으로만 설명합니다 (v4의 "색·모양으로 설명"을 바꿈).

dev 시험 (네이버 로그인 모양 화면, 시나리오 5개 × 2회, 10/10):

| 아이디 칸 | 비밀 칸             | 결과                                                                    |
| --------- | ------------------- | ----------------------------------------------------------------------- |
| 빔        | 빔                  | 아이디 칸 `suggest`                                                     |
| 참        | 빔                  | 비밀 칸 `suggest`, `chips: []`, "비밀번호 칸을 눌러 직접 입력해 주세요" |
| 참        | 참                  | "다 쓰셨으면 화면 가운데 '로그인' 버튼을 눌러 주세요" (`highlight`)     |
| 참        | 참 (안내 기록 없음) | 같음                                                                    |
| 빔        | 참                  | 아이디 칸으로 돌아감                                                    |

### `guide@v4.7` (2026-11-27): 저장된 계정으로 로그인하는 창은 먼저 묻기

고령자 앱 시험 중, 크롬의 "저장된 비밀번호를 사용하시겠습니까?" 창(`nid.naver.com`)에서 비밀 칸이 `filled`로 와서 AI가 "잘하셨어요. 화면 아래쪽 '로그인' 버튼을 눌러 주세요"라고 안내했습니다. 그 창은 누르는 순간 저장된 계정으로 바로 로그인되고, 저장된 계정이 가족 계정일 수도 있습니다.

- 저장된 계정·비밀번호로 로그인하는 창(크롬, 삼성 패스, 구글 비밀번호 관리자, "저장된 계정으로 계속" 등)이면 **바로 누르게 하지 않고 먼저 묻습니다**: `ask` "휴대폰에 저장된 계정으로 로그인할까요? 화면의 계정이 어르신 계정이 맞으세요?" `options: ["네", "아니요"]`
- 계정 아이디·이름은 말하지 않고 화면을 보시게 합니다. 어르신이 직접 입력하지 않았으므로 칭찬하지 않습니다.
- "네" → 로그인(사용) 버튼, "아니요" → 창을 닫거나 다른 계정·직접 입력
- 창의 사이트 주소가 공식 주소가 아니면 가짜 사이트 규칙대로 `stopped`
- 앱 쪽 변경은 없습니다. 답은 6장대로 `userReply`·`history`로 보냅니다
