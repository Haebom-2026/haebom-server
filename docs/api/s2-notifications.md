# S2 API: 알림 (민감 앱·막힘·SOS)

- 작성일: 2026-11-26
- 대상: 고령자 앱 (#6·#7·#8), 보호자 앱 (#21·#22, FCM)
- 상태: **dev 배포 완료**
- 기준: 지침서 4장·5.4·5.6·8장, [서버 기획](../server-plan.md) 4.2·6장, 보호자 앱 검토 답변 2.5 (FCM)

공통 규칙(Base URL, 인증, Idempotency-Key, 오류 형식)은 [S1 문서 1장](s1-users-links.md#1-공통)과 같습니다. 모든 경로는 `POST /v1/users/me`로 역할을 등록한 뒤 부를 수 있습니다.

---

## 1. 흐름

```
고령자 앱 ── #6·#7·#8 ──▶ 서버: 연결된 보호자 찾기 → 원본 1개 + 보호자별 알림함 저장
                                   └─ 보호자마다 FCM (kind: notification)
보호자 앱 ◀── FCM ── 받으면 #21 조회 → 상세 → #22 읽음
```

- 받을 보호자는 **서버가 연결 목록에서 정합니다.** 앱은 보호자를 지정하지 않습니다.
- 연결된 보호자가 없으면 아무것도 저장하지 않고 `no_guardians`를 돌려줍니다.
- 문자(SMS)는 서버와 관계없이 고령자 앱이 항상 보냅니다 (SOS·막힘).
- 화면 내용, 금액, 계좌는 보내지도 저장하지도 않습니다. `reason`·`appName`의 숫자 개인정보는 서버가 `***`로 가립니다.

## 2. 고령자 앱

세 경로 모두 role=elder만 부를 수 있고, `Idempotency-Key`를 받습니다. 재시도할 때 같은 키를 쓰면 알림이 두 번 생기지 않습니다.

### #6 `POST /v1/elder/sensitive-entries`: 민감 앱 알림

L1 이상 명령에서 어르신이 "보호자에게 알릴까요?"에 **예**를 눌렀을 때 부릅니다.

```json
{
  "packageName": "viva.republica.toss",
  "appName": "토스",
  "level": "L1",
  "category": "finance",
  "reason": "은행 앱 열기"
}
```

| 필드          | 필수 | 규칙                                                                                 |
| ------------- | ---- | ------------------------------------------------------------------------------------ |
| `packageName` | ✅   | 200자까지                                                                            |
| `appName`     | ✅   | 100자까지                                                                            |
| `level`       |      | `L0`~`L3`, 없으면 `L1`                                                               |
| `category`    |      | `finance`, `identity`, `public`, `device`, `privacy`, `scam`, `none` (없으면 `none`) |
| `reason`      |      | 100자까지                                                                            |

**같은 어르신·같은 패키지는 10분에 한 번**만 알림이 만들어집니다. 응답·안내 문구는 지침서 5.4 그대로입니다.

| HTTP | 응답                                                                      | 어르신 안내                                                |
| ---- | ------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 201  | `{ "result": "created", "notificationId": "n2026…", "guardianCount": 2 }` | "{보호자}에게 알림을 보냈어요."                            |
| 200  | `{ "result": "duplicate_suppressed" }`                                    | "조금 전에 이미 알렸어요."                                 |
| 200  | `{ "result": "no_guardians" }`                                            | "아직 연결된 가족이 없어요. 앱에서 가족 연결을 해 주세요." |
| 오류 | 네트워크·5xx                                                              | "보호자에게 보내지 못했어요. 인터넷 연결을 확인해 주세요." |

### #7 `POST /v1/elder/stuck`: 막힘

같은 안내에서 45초 동안 진행이 없을 때 부릅니다 (작업당 1번).

```json
{ "packageName": "kr.go.minwon.m", "appName": "정부24" }
```

앱 밖이면 두 값 모두 빈 문자열이거나 생략해도 됩니다. **중복 방지는 없습니다.**

### #8 `POST /v1/elder/sos`: SOS

SOS 버튼, "도와줘", 사기 의심(L3) 멈춤에서 [보호자에게 연락]을 눌렀을 때 부릅니다. **누를 때마다 보내고, 중복 방지는 없습니다.**

```json
{ "packageName": "", "appName": "", "category": "scam", "reason": "기관 사칭 송금 요청" }
```

`category`, `reason`은 선택입니다. `category: "scam"`이면 서버가 `level: "L3"`로 저장하고, 보호자 앱에서 가장 급한 알림이 됩니다.

#7·#8의 응답은 #6과 같습니다 (`created` 201 / `no_guardians` 200).

## 3. 보호자 앱

### #21 `GET /v1/guardian/notifications`: 알림 목록

최신순입니다. **연결을 해제한 어르신의 알림은 나오지 않습니다** (해제할 때 그 보호자 알림함에서 지움).

| 쿼리     | 규칙                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| `limit`  | 1~50, 기본 20                                                                                    |
| `cursor` | 앞 응답의 `nextCursor` (다음 페이지)                                                             |
| `since`  | ISO 8601. 이 시각 **뒤에** 생긴 알림만. 앞 응답의 `serverTime`을 그대로 넣습니다 (iPhone 폴링용) |

```json
{
  "items": [
    {
      "id": "n20261126T101621625Z-398b1c",
      "elderId": "e_1",
      "elderName": "김순자",
      "elderLabel": "어머니",
      "type": "sensitive_entry",
      "packageName": "viva.republica.toss",
      "appName": "토스",
      "level": "L1",
      "category": "finance",
      "reason": "은행 앱 열기",
      "createdAt": "2026-11-26T10:16:21.625Z",
      "readAt": null
    }
  ],
  "nextCursor": "Tk9USSNu…",
  "serverTime": "2026-11-26T10:16:25.324Z"
}
```

| 필드                          | 설명                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `type`                        | `sensitive_entry` / `stuck` / `sos`                                                                         |
| `level`, `category`, `reason` | 값이 있을 때만 옵니다. 막힘은 보통 없음                                                                     |
| `elderName`, `elderLabel`     | **알림이 만들어질 때**의 이름·호칭. 나중에 호칭을 바꿔도 이전 알림은 그대로입니다. 최신 호칭은 #20을 쓰세요 |
| `readAt`                      | 이 보호자가 처음 읽은 시각, 안 읽었으면 `null` (보호자마다 따로)                                            |
| `nextCursor`                  | 다음 페이지가 있을 때만                                                                                     |

표시 규칙은 지침서 8.2를 따르되, **전화 걸기는 없습니다** (서버와 보호자 앱 모두 어르신 전화번호를 받지 않음). 사기 의심(`category: "scam"` 또는 `level: "L3"`)은 어떤 `type`이든 가장 위에 빨간 강조 + "바로 연락해 확인해 주세요" 안내입니다.

### `GET /v1/guardian/notifications/{id}`: 한 건 조회

FCM 알림을 눌러 상세를 열 때 씁니다 (보호자 앱 요청). 응답은 #21 `items` 항목 하나와 같은 모양입니다. 없는 알림, 연결을 해제한 어르신의 알림, 보관 기간이 지난 알림은 `404 not-found`입니다.

### #22 `POST /v1/guardian/notifications/{id}/read`: 읽음

본문 없음. 성공하면 **204**입니다. 이미 읽은 알림은 처음 읽은 시각을 유지합니다. 없는 알림(해제·보관 기간 지남)은 `404 not-found`입니다.

### `POST /v1/guardian/notifications/read-all`: 모두 읽음

보호자 앱의 "모두 확인"에 씁니다 (보호자 앱 요청). 안 읽은 알림만 지금 시각으로 읽음 처리하고, 이미 읽은 알림은 처음 읽은 시각을 유지합니다.

```json
// 요청: 본문 없음 → 전체, elderId 를 주면 그 어르신 알림만
{ "elderId": "e_1" }
// 200
{ "updated": 3 }
```

## 4. FCM (보호자 앱 요청 2.5)

보호자 알림함에 항목이 생기면 그 보호자의 등록된 모든 기기(#4)에 보냅니다.

```json
{
  "data": {
    "kind": "notification",
    "id": "n20261126T101621625Z-398b1c",
    "type": "sensitive_entry",
    "elderId": "e_1"
  },
  "notification": { "title": "해봄 가족", "body": "새 가족 알림이 도착했습니다." }
}
```

| 종류                                          | `data.type`       | Android 채널      | 우선순위 | title                 | body                                                      |
| --------------------------------------------- | ----------------- | ----------------- | -------- | --------------------- | --------------------------------------------------------- |
| 민감 앱                                       | `sensitive_entry` | `family_activity` | 보통     | 해봄 가족             | 새 가족 알림이 도착했습니다.                              |
| 막힘                                          | `stuck`           | `help_alerts`     | 높음     | 해봄 가족 · 도움 필요 | 가족에게 도움이 필요할 수 있습니다. 앱에서 확인해 주세요. |
| SOS                                           | `sos`             | `sos_alerts`      | 높음     | 해봄 가족 · 긴급      | 가족이 도움을 요청했습니다. 앱에서 확인해 주세요.         |
| 사기 의심 (`category: scam` 또는 `level: L3`) | 그대로            | `sos_alerts`      | 높음     | 해봄 가족 · 긴급      | 〃                                                        |

- 문구는 보호자 앱이 앱 안에서 띄우는 문구와 같습니다 (보호자 앱 S2 검토). 앱 이름·내용은 넣지 않습니다.
- 앱은 `data.id`로 상세를 열고, `data.elderId`로 그 어르신 목록만 새로 고칠 수 있습니다.
- 채널(`family_activity`, `help_alerts`, `sos_alerts`)은 보호자 앱이 미리 만들어 두어야 합니다.
- iPhone은 Firebase에 APNs 키가 등록돼야 받습니다. 그전에는 `since` 폴링을 씁니다.

## 5. 보관

- 알림은 **90일** 뒤 자동으로 지워집니다.
- 연결을 해제하면 그 보호자의 알림함에서 그 어르신 알림을 바로 지웁니다. 원본은 90일 동안 남습니다.

## 6. 확인 상태

- 단위 테스트: 알림 시나리오 16개(한 건 조회·모두 읽음 포함) + FCM 형식·채널·문구 테스트
- dev 실제 확인: `no_guardians` → 연결 → #6 생성·Idempotency 재시도·10분 중복 방지 → #7 → #8 사기 의심(L3, 금액 가림) → #21 페이지·`since` → #22 → 해제 후 목록이 빔
- FCM: 실제 서비스 계정으로 화면 알림(채널·우선순위 포함)을 보내 FCM이 형식을 받아들이는 것까지 확인 (가짜 토큰이라 토큰 오류로 끝남)
- **아직 확인하지 않은 것**: 실제 폰에서 알림이 뜨는지, 채널별 소리·진동. 보호자 앱 연동 때 확인 부탁드립니다.
