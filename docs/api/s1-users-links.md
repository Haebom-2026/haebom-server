## 1. 공통

| 항목           | 값                                                                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base URL (dev) | `https://qq829otaql.execute-api.ap-northeast-2.amazonaws.com`                                                                                                          |
| 인증           | `Authorization: Bearer <Firebase ID 토큰>`. Firebase 프로젝트 `copilot-demo-c9a74`. 고령자 앱은 익명 로그인 토큰                                                       |
| 형식           | `Content-Type: application/json; charset=utf-8`. 시간은 ISO 8601 UTC (`2026-11-26T06:00:00.000Z`)                                                                      |
| uid            | 본문에 넣지 않습니다. 서버가 토큰의 `sub`로 본인을 정합니다                                                                                                            |
| 역할           | `/v1/elder/*`는 role=elder, `/v1/guardian/*`는 role=guardian만 부를 수 있습니다                                                                                        |
| 중복 요청      | #11·#14는 `Idempotency-Key: <8~128자 [A-Za-z0-9_-], UUID 권장>`를 받습니다. 재시도할 때는 같은 키를 쓰면 첫 응답이 그대로 옵니다 (응답 헤더 `idempotent-replay: true`) |

### 오류 형식

```json
{ "error": { "reason": "code-expired", "message": "Connect code has expired" } }
```

앱은 `reason`만 보고 분기합니다. `message`는 개발용이며 바뀔 수 있습니다.

> **예외**: 토큰이 없거나 만료되면 API Gateway가 `401 {"message":"Unauthorized"}`로 응답합니다. 이 경우만 형식이 다르니, **401은 상태 코드로만** 판단해 주세요.

### 공통 reason

| HTTP | reason              | 언제                                                  | 앱 처리                           |
| ---- | ------------------- | ----------------------------------------------------- | --------------------------------- |
| 401  | (본문 형식 다름)    | 토큰 없음·만료                                        | 토큰을 새로 받아 1번 재시도       |
| 403  | `profile-required`  | 프로필 미등록                                         | #2 호출 후 1번 재시도             |
| 403  | `permission-denied` | 다른 역할의 경로를 부름                               | 재시도 없음                       |
| 400  | `invalid-argument`  | 본문·경로 형식 오류, 같은 Idempotency-Key로 다른 요청 | 재시도 없음                       |
| 404  | `not-found`         | 없는 경로, 해제할 연결이 없음                         |                                   |
| 409  | `conflict`          | 다른 role로 재등록, 같은 키의 요청이 처리 중          |                                   |
| 503  | `unavailable`       | 일시 장애                                             | 같은 Idempotency-Key로 1번 재시도 |
| 500  | `internal`          | 서버 오류                                             |                                   |

## 2. 사용자

### #2 `POST /v1/users/me`: 역할·이름 등록

앱을 처음 시작할 때 1번 부릅니다. 이미 같은 역할로 등록돼 있으면 기존 프로필을 돌려주므로 매번 불러도 됩니다.

```json
// 요청
{ "role": "elder", "name": "김순자" }
```

| 필드   | 필수 | 규칙                       |
| ------ | ---- | -------------------------- |
| `role` | ✅   | `elder` 또는 `guardian`    |
| `name` |      | 40자까지, 없으면 빈 문자열 |

```json
// 201 처음 등록 / 200 이미 같은 역할로 등록됨 (이름은 바뀌지 않음, 바꾸려면 #3)
{ "uid": "Xk2…", "role": "elder", "name": "김순자", "createdAt": "2026-11-26T06:00:00.000Z" }
```

| 실패                    | reason         |
| ----------------------- | -------------- |
| 다른 역할로 이미 등록됨 | `409 conflict` |

### #3 `PATCH /v1/users/me`: 이름 변경

```json
{ "name": "김순자" }
```

200으로 #2와 같은 모양을 돌려줍니다. 연결된 상대방 목록(#18·#20)에 보이는 이름도 함께 바뀝니다.

## 3. 기기 (FCM 토큰)

### #4 `PUT /v1/devices/{deviceId}`: 토큰 등록·갱신

- `deviceId`: 앱이 처음 실행할 때 만든 UUID (8~64자 `[A-Za-z0-9_-]`). 디버그 뷰어 heartbeat와 같은 값을 씁니다.
- 토큰이 바뀔 때(`onNewToken`)마다 다시 부르면 됩니다.

```json
{ "fcmToken": "<FirebaseMessaging.getToken()>", "platform": "android" }
```

`platform`: `android` / `ios` / `web`. 성공하면 **204**입니다.

> 앱을 다시 설치해 익명 uid가 바뀌어도 같은 `deviceId`로 등록하면, 이전 uid에 남아 있던 토큰은 서버가 지웁니다. 다른 사람에게 푸시가 가지 않게 하기 위해서입니다.

### #5 `DELETE /v1/devices/{deviceId}`: 토큰 해제

로그아웃·알림 끄기 때 부릅니다. 없는 기기여도 **204**입니다.

## 4. 연결

연결 1쌍(어르신 1명 ↔ 보호자 1명)이 데이터 1개입니다. 한 어르신에 보호자 여럿, 한 보호자에 어르신 여럿이 될 수 있습니다.

### 호칭 필드

| 필드            | 뜻                                 | 예     | 비어 있을 때 앱 표시      |
| --------------- | ---------------------------------- | ------ | ------------------------- |
| `elderLabel`    | 보호자 앱에서 어르신을 부르는 호칭 | 어머니 | `elderName`               |
| `guardianLabel` | 고령자 앱에서 보호자를 부르는 호칭 | 큰딸   | `guardianName` → "보호자" |

서버는 빈 값을 그대로 저장합니다. 대체 표시는 앱이 정합니다. `relationship`은 쓰지 않습니다.

### #11 `POST /v1/elder/connect-codes`: 연결 코드 발급 (고령자)

- 본문 없음. `Idempotency-Key` 권장.
- 6자리, **10분**, 일회용입니다.
- **새 코드를 받으면 이전 코드는 바로 무효**가 됩니다.

```json
// 201
{ "code": "371715", "expiresAt": "2026-11-26T09:05:46.573Z" }
```

### #14 `POST /v1/guardian/links`: 코드로 연결 (보호자)

`Idempotency-Key`를 붙여 주세요. 연결은 됐는데 응답을 못 받았을 때, 같은 키로 재시도하면 `already-linked` 대신 첫 성공 응답이 옵니다.

```json
// 요청
{ "code": "371715", "elderLabel": "어머니", "guardianLabel": "큰딸" }
```

| 필드                          | 필수 | 규칙                          |
| ----------------------------- | ---- | ----------------------------- |
| `code`                        | ✅   | 숫자 6자리                    |
| `elderLabel`, `guardianLabel` |      | 각 20자까지, 없으면 빈 문자열 |

```json
// 201
{
  "elderId": "Xk2…",
  "elderName": "김순자",
  "elderLabel": "어머니",
  "guardianLabel": "큰딸",
  "connectedAt": "2026-11-26T08:55:48.290Z"
}
```

| 상황                                | HTTP | reason              | 보호자 앱 문구 예                                   |
| ----------------------------------- | ---- | ------------------- | --------------------------------------------------- |
| 없는 코드                           | 404  | `invalid-code`      | 코드를 다시 확인해 주세요.                          |
| 10분 지남                           | 409  | `code-expired`      | 코드 시간이 지났어요. 새 코드를 받아 주세요.        |
| 이미 사용됨 / 새 코드 발급으로 무효 | 409  | `code-used`         | 이미 쓴 코드예요. 새 코드를 받아 주세요.            |
| 이미 연결된 어르신                  | 409  | `already-linked`    | 이미 연결된 가족이에요. (이때 코드는 소모되지 않음) |
| 틀린 코드를 너무 많이 입력          | 429  | `too-many-attempts` | 잠시 후 다시 시도해 주세요.                         |

> **입력 제한**: 보호자 한 명이 10분 안에 5번 틀리면 그 10분 구간이 끝날 때까지 막힙니다. 서버 전체로 1분에 60번 넘게 틀린 입력이 오면 잠시 모두 막힙니다 (무차별 대입 방지). `invalid-code`, `code-expired`, `code-used`가 틀린 입력으로 셉니다.

### #15 `DELETE /v1/guardian/links/{elderId}`: 보호자 쪽 해제

## 5. FCM: 연결 변경 알림

연결이 **생기거나 지워지면**, 서버가 그 어르신과 보호자의 **등록된 모든 기기**(#4)에 data 메시지를 보냅니다. 화면에 뜨지 않는 data 메시지이고, 안드로이드는 우선순위 HIGH입니다.

```json
{ "kind": "link", "change": "created", "elderId": "e_1", "guardianId": "g_1" }
```

| 키                      | 값                    |
| ----------------------- | --------------------- |
| `kind`                  | `link`                |
| `change`                | `created` / `deleted` |
| `elderId`, `guardianId` | 연결 당사자 uid       |

- 앱은 받으면 #18(고령자) 또는 #20(보호자)을 다시 조회합니다.
- 자기가 만든 변경에 대한 메시지도 옵니다 (예: 보호자가 연결하면 보호자 기기에도 옴). 다시 조회하면 되므로 따로 거를 필요는 없습니다.
- FCM은 빠질 수 있으니, **화면에 들어올 때도 조회**해 주세요.
- FCM이 무효 토큰이라고 답하면 서버가 그 기기 등록을 지웁니다. 앱은 시작할 때마다 #4로 토큰을 다시 등록하는 게 안전합니다.
- iPhone은 Firebase에 APNs 키가 등록돼 있어야 받습니다. 지금은 등록 전이라 iPhone은 폴링(화면 진입 시 조회)만 됩니다.

> **키 이름 확정 필요**: 보호자 앱 형식(`kind`, `id`)으로 구현했습니다. 고령자 앱 답변은 `type`, `approvalId`였습니다. S2·S3의 알림·승인 메시지도 같은 규칙을 쓸 예정입니다 (예: `{ "kind": "approval", "id": "a_789", "status": "approved", … }`). `type`은 알림 종류(`sensitive_entry`/`sos`/`stuck`)에만 씁니다.

## 7. 정해야 할 것

1. **FCM 키 이름**: `kind`로 통일해도 되는지 (고령자 앱)
2. **보호자 앱 로그인**: 익명 로그인은 앱을 다시 깔거나 폰을 바꾸면 uid가 바뀌어 **모든 연결이 끊깁니다**. Google 로그인 등 실제 계정 연결을 권합니다. Firebase에서 익명 계정을 실제 계정에 연결하면 uid가 그대로라 서버는 바꿀 게 없습니다.
3. **이전 dev 주소 폐기**: `9a2sj8hqlb…`, `d3jcc37k40jy8z…`는 삭제됐습니다. 위 Base URL을 써 주세요.
